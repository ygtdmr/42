GET

Erişim ve Yönlendirme (Routing)

  • 1. Ana Sayfa (Default Index) Yeni Sekme

    Kök dizindeki varsayılan HTML sayfasını yükler. Beklenen: 200 OK

  • 2. Alt Dizin Varsayılan Dosyası

    Belirli bir dizin istendiğinde yapılandırmadaki index dosyasının açılıp açılmadığını kontrol eder.

    Conf İpucu: location /klasor1/ { index page.html; }

  • 3. Dizin Listeleme (Autoindex AÇIK)

    İçinde index dosyası olmayan bir dizinin listesini tarayıcıda göstermelidir.

    Conf İpucu: location /autoindex_on/ { autoindex on; }

  • 4. Dizin Listeleme (Autoindex KAPALI)

    Autoindex'in kapalı olduğu dizine girişte sunucu hata vermelidir. Beklenen: 403 Forbidden

  • 5. HTTP Yönlendirme (Redirect)

    Bu adrese girildiğinde sunucu sizi başka bir URL'ye yönlendirmelidir. Beklenen: 301 veya 302

    Conf İpucu: return 301 http://google.com; veya return 301 /yeni_sayfa;

  • 6. Özel Hata Sayfası Testi (404 Not Found)

    Var olmayan bir URL. Sunucunuz kendi tanımladığınız özel hata sayfasını (HTML) döndürmelidir.

    Conf İpucu: error_page 404 /custom_404.html;

POST

Veri İletimi ve Sınırlar

1. Standart Form Gönderimi

2. Dosya Yükleme (File Upload)

Seçilen dosya sunucuda belirlenen yükleme (upload) dizinine kaydedilmelidir.

3. Body Limit Testi (413 Payload Too Large)

Bu buton, sunucuya tek seferde ~10 Megabayt boyutunda devasa bir metin gönderir. Conf dosyanızdaki limit küçükse sunucu bu isteği reddetmelidir.

Conf İpucu: İlgili route'da client_max_body_size 1M; veya benzeri bir ayar yapın.

DELETE & SECURITY

Silme ve İzin Kontrolleri

1. Başarılı Dosya Silme (DELETE)

Hedeflenen dizinde var olan bir dosyayı silebilir olmalısınız.

2. İzin Verilmeyen Metot (405 Method Not Allowed)

Sadece GET isteği kabul eden bir sayfaya POST veya DELETE atmayı dener. Sunucu 405 hatası döndürmelidir.

3. Sunucu Dayanıklılık Testi (UNKNOWN METHOD)

Geçersiz veya RFC'de olmayan bir HTTP metodu gönderilir. Sunucu kesinlikle çökmemeli (crash) ve uygun hatayı (örn: 501 Not Implemented veya 400 Bad Request veya 405 Method Not Allowed) döndürmelidir.

TERMINAL

Host, Port ve Stres Testleri

Aşağıdaki testler tarayıcıdan yapılamaz, değerlendirmecinin bu komutları yeni bir terminal penceresinde çalıştırması gerekmektedir.

1. Çoklu Hostname (Virtual Host) Testi

Aynı portta (örn 8080) farklı `server_name` yapılandırmalarının doğru siteyi açıp açmadığını test eder.

curl --resolve site1.com:8080:127.0.0.1 http://site1.com:8080/
curl --resolve site2.com:8080:127.0.0.1 http://site2.com:8080/

2. Port Çakışması Kontrolü

Yapılandırma dosyanızda aynı portu iki farklı server bloğunda aynı isimle veya hataya yol açacak şekilde tanımlayın. Sunucu düzgün bir hata ile kapanmalı veya kurala göre davranmalıdır.

3. Siege ile Stres ve Sızıntı Testi

Sunucunun Availability (Erişilebilirlik) oranı %99.5'in üzerinde olmalı ve bellek sızıntısı (memory leak) yapmamalıdır.

# Htop veya Leaks programını yanda açık tutun siege -b http://localhost:8080/

* Not: I/O Multiplexing (select, poll, epoll vs.) döngüsünde fd (file descriptor) sızıntısı olmadığından emin olun. Hata alan veya kapanan client'ların soketlerini kapattığınızı lsof -i :8080 ile kontrol edebilirsiniz.
